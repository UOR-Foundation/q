# Security policy

## Reporting vulnerabilities

The [Foundation security policy](https://github.com/UOR-Foundation/.github/blob/main/SECURITY.md) applies to Q. Follow its published private reporting routes (GitHub Security Advisories where available, or the Foundation's published security email). Do not publish sensitive vulnerability details in a public issue, Discord channel, or skill feedback.

The availability of Q-specific private advisory intake and actual delivery through the published contact have not been independently verified in this repository. Do not claim that either has been tested.

## Response

The Foundation security policy establishes severity targets, triage, remediation, patching, responsible disclosure and post-incident review. Q's accountable incident triage owner and any repository-specific escalation delegation remain NOT_ESTABLISHED.

For Q, incident review should consider the affected kernel and host revision, Discord permissions and data, web/MCP exposure, stored records, credentials and signed artifacts as applicable. Preserve evidence without publicly exposing secrets or private message content. This is scope guidance, not new operational authority.

## Supported versions

Q-specific supported versions and the security-fix policy are NOT_ESTABLISHED. Do not infer them from the host package version or signed artifact publication.

Track unresolved owner decisions in [governance remediation #6](https://github.com/UOR-Foundation/q/issues/6).
